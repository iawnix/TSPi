[English](PLAN_CAPABILITY_DRIVEN_RESEARCH.md) | 简体中文

日期：2026-09-16。

状态：M0–M7 的首版实现与试用验收已完成。本文件保留设计取舍和验收标准；
实际支持边界、试验限制及条件性后续项见能力目录和运维文档；一次性验收报告不作为
仓库文件保留。

## 当前实施状态（2026-09-16）

首版提供 22 项可独立调用的分析能力，涵盖反应解析与守恒、有界映射候选、键变化、
端点重排、片段布置、物种身份、Gaussian 输入与输出、路径候选、振动/IRC 证据、
基元步骤审计、热化学、势垒、TST、受限分支比较及化学网络/能量曲线。
扩展和原生 App Server 共用 `ts_analyze` 请求合同；能力详情按需查询。

结果使用 Node-owned artifact、Activity 与 `ts-analysis-observation-candidates/1`。
已有 `ts_change` 负责提升选定事实，重算输入和生成文件以验证来源；多输入角色的
JSON 顺序不影响校验。没有新增全局物种注册表、伪造 compute intent 或下一步路由。

`ts_manage` 暂缓/恢复指定开放 Node 的新派发，使用独立操作回执链，不增加科学
状态枚举；已有作业仍能查看、收集、解析和精确取消。`ts_calc finalize` 可从绑定
intent 推导主输出路径；模板 ProofSpec 可推导 title；直接 Observation 可从 artifact
ID 推导 digest。协议错误会提示局部引用、datatype、severity 等具体字段。

报告和只读 Web 已展示分析、证据来源、能量/速率、网络参与物与派发状态。新增
`tspi-mechanism` 按问题提供参考，没有固定计算序列。使用方法见
[运维文档](SCIENTIFIC_CAPABILITIES_OPERATIONS.zh-CN.md)，设计决定见
[ADR 0002](adr/0002-independent-scientific-capabilities.md)。当前证据以源码测试、
组件测试和发布检查为准。

## 1. 目标与首版范围

目标是让 Agent 根据科学问题、已有结果、用户意见和预算，自主选择与组合能力，
开展过渡态和反应机制研究。人通过细粒度 ResearchNode 理解过程、定位文件、
讨论结果、调整研究方向，并管理具体节点的后续工作。

首版聚焦基态分子体系中的经典过渡态与有限候选机制比较，优先验证闭壳层及
离子反应、气相与有明确定义的隐式溶剂条件。电荷、自旋态及适用范围始终显式
记录。开放壳层、跨自旋面、激发态、界面等问题可以被表达，但只有对应能力和
证据齐备时才能给出该领域的验证结论。

首版应支持三种入口：只有反应定义；已有反应物/产物结构；已有 TS 候选或
计算输出。Agent 可以从任何适合的证据起点开始，不要求重新执行统一流程。

开发里程碑规定软件实现的依赖，不规定化学研究的计算顺序。

## 2. 已确认的设计约束

1. Root Agent 决定科学问题、方法、分支、回溯、证据解释和停止条件。
2. 能力声明能接受什么、产生什么及其限制，不包含下一科学动作路由。
3. 保留 ResearchPhase、ResearchNode、Claim 的职责划分和细粒度 Node。
4. 科学状态继续由 Kernel 通过 Decision 事务持久化，沿用 `ts_change`。
5. 技术字段尽量由系统生成；科学意图、假设和判断由 Agent 明确给出。
6. 能力结果、程序成功、科学支持和最终接受分别表达。
7. Web 和报告消费只读投影；科学状态只有一个权威来源。
8. Node DAG 和 Claim 关系图描述研究与论证；化学反应网络独立表达化学连接。
9. 不设置固定的 `CREST → NEB → Gaussian → IRC` 流程，不根据标签、节点名称、
   ProofSpec 结果自动创建下一研究问题。
10. 不因增加能力而给每个工具、物种或计算候选强制建立一套新的管理生命周期。

依据：[ADR 0001](adr/0001-phase-node-research-kernel.md)、
[假设与证明循环](PLAN_HYPOTHESIS_PROOF_LOOP.zh-CN.md)、
[状态模型](../skills/tspi-orchestration/references/state_model.md)。

## 4. Node：保留记录粒度，降低维护负担

### 4.1 分层职责

| 对象 | 回答的问题 | 维护方式 |
| --- | --- | --- |
| Phase | 这部分工作属于哪个研究主题？ | 保留必需归属，允许显式选定现有 Phase 后复用 |
| Node | 这一段研究做什么、结果在哪、如何讨论和继续？ | Agent 决定科学边界，Kernel 处理身份和持久化 |
| Claim | 哪个科学陈述正在被检验？ | 多个 Node 可研究同一 Claim；探索 Node 可以没有 Claim |
| Attempt / Activity | 具体调用如何执行，产生了哪些文件？ | 系统记账，重试和运行细节留在 Node 下 |
| Observation / Finding | 哪些事实、异常和限制需要引用？ | Agent 核验并选择，系统绑定来源 |
| ProofSpec / Acceptance | 声明的证据标准是否满足？ | 冻结规则后确定性评价，接受与 Node 完成分开 |

### 4.2 Node 拆分规则

保留候选生成、驻点/模式评估、IRC 端点归属、竞争路径比较等可分别查阅和干预的
研究单元。拆分依据是独立的问题、主要交付物和交互价值，而非软件名称或固定步骤。

优化迭代、轮询、收集文件、相同问题内的重试和方法参数变体不单独成为路线图节点。
记录证据、冻结 ProofSpec 等记账操作也不单独成为科学节点。

Agent 可以临时插入一个节点、选择其他能力、保留未决分支或从早期节点回溯。
不要求每项研究都出现所有类型的节点，不设置 Node 类型到后续能力的映射。

首版保留“一次 Decision 最多开一个、关一个 Node”的现有约束。直接衔接时利用
已有原子关闭/打开能力；不为减少调用数而丢失各节点的研究理由。批量创建或新建
节点状态枚举仅在实测有必要且完成 ADR 后考虑。

### 4.3 人与 Agent 的节点交互

Node 详情应能定位问题、当前活动、结果、待解决问题、相关 Claim、证据与文件。
上下文使用指定节点及必要邻域；完整历史按需读取。

通过现有 Agent 会话/原生 App Server 接收以下交互语义：

| 用户意图 | 处理方式 | 记录与执行边界 |
| --- | --- | --- |
| 解释 node_7 | 读取该节点及引用的证据 | 只读，不改变计算 |
| 暂缓 node_7 后续工作 | 停止在该范围派发新的研究计算/分析 | 在途作业状态仍可检查，是否继续与收集策略明确记录 |
| 取消 node_7 的某项计算 | 解析到准确 Attempt 并走现有 cancel | 保留取消回执和未知结果，不影响其他节点 |
| 恢复暂缓的研究 | 移除相应操作暂停约束，重新读取证据 | 开放节点可继续；终态节点通过新依赖节点继续 |
| 从 node_7 换一种假设研究 | Agent 给出变更理由并新建依赖节点 | 引用原 artifact，不改写旧历史 |
| 优先研究某个分支 | 调整 Agent 工作焦点和后续选择 | 不自动取消其他分支的作业 |

管理意图需要携带明确 workspace/Node/Attempt 范围、发起者与操作回执。
操作暂停、Agent 生成中止、远端作业取消和科学否定分别表达。

优先复用操作日志和 Host 控制记录；确需新增字段时增加最小操作合同，不把
`paused` 随意混入科学终态。涉及派发的暂停检查必须在执行边界生效；已经越过
派发边界的任务应明确列为在途任务，不承诺无法保证的“立即无作业运行”。

TS Web 继续只读展示这些状态。此规划不新增绕过 Host/Kernel 的 Web 写接口。
图中的节点编号可直接用于现有会话指令；专门管理按钮可在后续客户端方案中实现。

## 5. 协议减负：优先改善现有接口

### 5.1 保留的严格性

保留原子事务、版本绑定、artifact digest、来源、作业回执、未知副作用处理、
Claim/ProofSpec/Acceptance 的独立含义。计算结束不自动关闭 Node；Node 关闭不
自动接受 Claim。正式验收需要的标准不得因接口精简而减少。

Agent 仍需明确研究问题、假设、方法理由和结论。系统不自动编造反证条件、
不确定性、物种身份或科学结果。

### 5.2 有针对性的改动

1. 优化 `ts_change` 的现有操作模板和按需合同查询；不建立第二套研究状态 API。
2. 系统维护技术 ID、时间、路径、hash、producer/version、活动关联等已知字段。
   复用当前已实现部分，新增工作只处理仍由 Agent 重复搬运的字段。
3. 合并一次决策内的证据登记、Finding、ProofSpec 评价和状态更新，继续遵守现有
   单次 Node 开关规则及科学语义。
4. 对由模板唯一决定的 dimension/title、由已绑定运行唯一决定的默认输出文件等，
   提供确定性展开；展开内容可检查并进入记录。存在歧义时返回候选，不猜测。
5. 返回稳定错误码、准确字段位置、冲突对象和必要的合同片段，减少“报错后通读文档”。
6. `ts_state` 提供小型能力索引、指定能力详情、Node 局部上下文和 delta。
   不将所有新能力的完整 schema 与所有 Node 历史常驻上下文。
7. 默认返回摘要、关键诊断、artifact/candidate 引用；长轨迹、映射表和全量网络按需读取。
8. 复用明确且仍有效的 Phase、资源 profile 等技术上下文，并把最终绑定写入记录。
   不静默改变科学输入、电荷、自旋、溶剂或计算方法。

### 5.3 扩展候选事实机制

当前 `ts-observation-candidates/1` 绑定 `calc_*` intent，不能直接代表普通分析活动。
应复用候选值、单位、来源和概念字段，设计能够区分 compute 与 analysis producer
的最小版本化绑定。不得给本地分析伪造 calculation intent。

Agent 检查后选择 candidate 并给出必要的主体归属和解释；Kernel 验证来源、版本、
所属 Node 和 digest。能从绑定推导的 provenance 不要求 Agent 再填写。

保留同 Node 候选提升规则。跨 Node 使用已登记 Observation 或原 artifact 的显式
引用；独立再分析会生成新活动和来源记录，不改写 candidate 的生产归属。

原始输出先留在 artifact/Attempt 中，只有用于科学陈述的事实才需要提升。
这不意味着延迟已有假设的登记：确认性预测与反证条件仍应在检验前记录；
从探索数据得到的新假设应标明其来源，不能倒填成预注册假设。

### 5.4 计算生命周期便利化

先消除 finalize 的重复路径填写、资源配置搬运和冗余轮询上下文。保留
`launch/inspect/finalize/cancel` 的可观察性和精确操作语义。

只有 M0 基线证实运行维护负担显著时，再实施 Host 管理的单能力异步运行便利层：
它负责一次已授权调用的状态检查、收集和解析，不选择下一科学能力，不自动
重算或更换方法，不据程序结束自动接受 Claim。

便利层需支持持久运行句柄、进度、取消、中断恢复、幂等重放和未知提交的协调。
对同一运行的旧接口与便利层共享操作守卫，避免重复提交或重复收集。
长任务不阻塞会话等待；用户仍可管理节点和在途作业。

## 6. 能力入口与实现边界

### 6.1 最小扩展方案

保持现有计算能力目录和 `ts_calc`。为新确定性科学分析提供 `ts_analyze`
统一入口，归属现有 artifacts extension，输出仍进入现有 artifact/Activity 系统。
查询通过扩展 `ts_state mode=capabilities` 暴露 analysis 目录。

已有 `ts_seed`、`ts_compare`、`ts_render` 等能力在发现层可被列出，但保持自己的
实现与稳定入口；不复制一份算法，也不为了统一命名先重写所有工具。

公共请求形状如下，输入角色和值以指定能力的 schema 为准：

```json
{
  "operation": "run",
  "nodeId": "node_12",
  "capability": "reaction.mapping.validate",
  "capabilityVersion": "1",
  "inputArtifacts": {
    "reactants": ["art_..."],
    "products": ["art_..."]
  },
  "parameters": {
    "mapping": [
      {"reactant": {"species": 0, "atom": 0}, "product": {"species": 0, "atom": 0}}
    ]
  }
}
```

输入支持有界、由能力 schema 定义的结构化参数。现有计算入口的标量参数表不能
直接用于映射数组和物种列表；分析入口应支持这类数据，长输入通过 artifact 引用。

执行框架只按精确 capability ID/version 调用已注册实现，不接受任意 shell、模块名
或由科学标签生成的可执行表达式。算法产生事实、指标和候选；科学解释仍归 Root。

### 6.2 能力描述的最低内容

常驻索引仅包含 ID、摘要、输入输出类型和能力类别；详细查询返回：

- 版本、参数 schema、输入与输出 artifact schema；
- 有副作用的范围、运行位置及可用性诊断；
- 数据前置条件、科学适用范围和限制；
- parser/分析实现版本、复现所需设置；
- 输出候选事实、已知失败模式、数据缺失的表达方式。

随机采样显式记录 seed；数值计算声明复现容差，不把所有科学计算声称为逐字节
确定。cost_hint 可作粗略可选信息，不伪造精确成本和可信度。

目录不包含 `next_capability`、`required_successor`、固定 workflow stage。
前置条件检查实际数据与方法兼容性，不要求输入必须来自某个前置软件。

### 6.3 结果合同

结果提供调用是否执行、输入输出引用、摘要、候选事实、诊断与适用范围。
科学数据缺失、映射歧义、算法截断、程序错误分别表达；不复用一个 `success`
同时代表执行成功、结果完整和机制成立。

结果均有 owning Node 和 Activity/Attempt 来源。能力不会直接改 Claim status。
依赖能力返回的句柄解析时必须校验其绑定，不能静默使用“最近一次结果”。

## 7. 科学能力建设清单

下表为首版能力分组，精确 ID、参数与限制以 capability catalog 为准。
每一项能力均可独立调用，表格顺序不是研究流程。

| 能力组 | 能力或复用入口 | 首版交付与限制 |
| --- | --- | --- |
| 反应定义 | `reaction.parse`、`reaction.validate` | 多反应物/产物、计量、角色、显式条件；检查守恒与缺项 |
| 原子映射 | `reaction.mapping.validate`、`reaction.mapping.generate` | 先验证显式映射，再提供有界候选；保留对称与氢映射歧义 |
| 键变化 | `reaction.bond_changes` | 从已选择映射提取成键、断键、键级变化与反应中心 |
| 结构准备 | `structure.reindex`、`structure.assemble_fragments` | 生成新的配对端点/片段布置 artifact，保留原结构及重排表 |
| 物种与构象比较 | 扩展 `ts_compare` 与身份分析 | 组合图、映射、电荷、自旋、立体化学、构象信息；不能只用 RMSD |
| TS 候选处理 | `path.extract_candidate`，复用扫描、CREST、ASE-NEB | 提取候选几何、端点和路径指标；路径峰值仍是候选 |
| Gaussian 输入衔接 | 扩展受限输入构造/导入能力 | 根据 Agent 指定设置构造 opt/freq/IRC/QST 输入；复用现有后端 |
| 振动分析 | `vibration.analyze_mode` | 提取位移与选定内坐标变化；为模式赋值提供证据 |
| 路径证据 | `path.endpoint_summary`、`mechanism.step.audit` | 记录方向、完成度、端点身份和缺失证据；不替 Agent 决定机制 |
| 热化学 | `thermochemistry.evaluate`、`barrier.evaluate` | 明确 E/ZPE/H/G、方法组合、条件与修正来源 |
| 基础动力学 | `kinetics.tst`、`kinetics.branching` | 支持适用条件明确的速率和共享前体竞争；保留假设 |
| 反应网络 | `mechanism.network.assemble`、`mechanism.network.audit` | 按显式输入建图，检查物种/步骤一致性、分支、环路和缺口 |
| 研究交付 | 扩展 `ts_render`、`ts_report` 与 projection | 能量图、网络、验证状态、速率表和源证据联动 |

### 7.1 反应输入、映射与结构准备

ReactionSpec 包含参与物种、两侧计量、角色、原始输入、研究条件及映射引用。
电荷与电子态记录在物种/明确的组合体系上，不用一个全局 multiplicity 替代所有
中间体的电子态。质子供体、受体、离子对、显式溶剂和参与催化剂需要明确表示。

守恒检查覆盖整个平衡反应。氢转移不允许反应两侧无说明地缺少原子；涉及储库、
质子/电子交换等开放体系时显式声明边界，首版不支持的模型返回限制。
自旋多重度不能像元素计量一样简单求和；检查电子数、允许态和声明的表面连续性。

自动映射先覆盖有界的普通分子反应。存在多个等价或不等价方案时返回候选与依据，
不宣称未经校准的“95% 置信度”。XYZ 推断键图具有模型依赖，阈值、方法和限制需要记录。

NEB 所需的原子次序由显式选定映射生成新端点 artifact；输入元素序列相同本身不足以
证明化学映射正确。片段相对布置由 Agent 提供约束/采样条件，能力可返回有限候选，
不能把一次任意拼接作为已优化反应物复合体。

### 7.2 TS 证据能力

继续使用现有 Gaussian、xTB、CREST 和 ASE-NEB 计算能力，先补足产物之间的衔接。
不为“TS 优化”重复实现另一套 Gaussian adapter。QST2/QST3 的候选策略和输入
构造可扩展，真正启动仍使用现有受限计算入口与能力校验。

分析能力应提供驻点收敛、虚频数量、模式位移、关键键变化、IRC 方向、有限端点和
结构比较结果。程序正常结束、一个虚频或 NEB 最高点均不足以单独证明目标 TS 成立。
有限 IRC 端点有时仍需优化才能归属盆地；是否继续由 Agent 根据证据决定。

保留 `accepted-ts` 的驻点、反应坐标和连通性含义。现有接受不自动扩大到跨自旋面、
非绝热、动力学分岔等问题。

### 7.3 热化学与势垒

复用 Gaussian 已有热化学解析，补全温度、压力、焓、熵、修正来源及完整性。
能量结果必须关联结构/物种、电子态、模型化学、溶剂、单位和条件。

支持显式选择的高层单点加低层热修正组合，记录各项来源和适用几何；不能把方法
不一致的能量静默拼接。频率缩放、标准态、低频处理、对称数和构象处理均要可追溯。
首版采用明确的谐振模型；准谐近似等方法在独立实现并有测试后增加。

按计量系数定义同一参考状态下的反应自由能、正反向势垒。TS 分配函数不包含
反应坐标对应的不稳定振动贡献；修正不得重复计入。缺失的量标为缺失，不用电子能
冒充自由能，也不自动从单一温度结果生成多温度热化学。

### 7.4 TST 与选择性

基础实现采用显式的温度、标准态和传输系数；首版默认模型可选 `kappa=1`，并在结果
中显示该假设。浓度形式、总反应级数为 m 的 elementary step，在约定的浓度标准态下：

```text
k_m(T) = kappa(T) * k_B*T/h * (c_standard)^(1-m)
         * exp(-DeltaG_activation_standard/(R*T))
```

因此一级和二级速率常数单位不同。速率常数与乘入实际浓度后的反应速率分别输出。
气相压力标准态与溶液浓度标准态必须明确换算，不能混用；非基元表观反应级数不直接
套入该式。

简单产物分支比例只用于共享前体、所声明的平衡/不可逆条件成立的模型。多步反应、
催化循环、回流和时间依赖应交给后续微观动力学能力；不能仅比较两个 TS 的绝对 G
或最高单步势垒就宣布主导路径、总速率决定步骤。

### 7.5 化学反应网络

采用物种节点与带计量系数的 reaction/step 节点或等价超边，正确表达 A+B → C+D。
可逆反应和催化循环允许有环。现有 Node/Claim 的 DAG 无环约束不能应用到化学网络。

同一物种可有多构象和电子态记录；物种身份、构象身份、能量记录身份分别处理。
同一对参与物种之间的多个 TS 不应自动合并。仅有近似结构相似性时返回候选合并建议。

Agent 提供需要合并的物种与步骤引用，确定性能力检查端点、计量、电荷/态、来源
和分支。自动生成的候选反应步骤如在后续加入，需声明生成规则和搜索范围，由 Agent
决定是否探索，不能将生成网络声称为完备机制。

路径枚举有深度、数量和循环展开边界，并报告截断。结构连通性、能量比较和动力学
结论分别呈现；图算法本身不产生机制接受结论。

## 8. 数据合同：科学 artifact 优先

初期不新增独立 `species.json`、`steps.json` 等全局可变注册表，也不为这些对象创建
单独状态机。使用带版本的 artifact payload，由现有 Node、Observation 和 Claim 引用。

| Payload | 最小科学内容 | 第一使用场景 |
| --- | --- | --- |
| ReactionSpec | 参与物种、计量、角色、输入、条件、边界 | 反应输入与映射 |
| MappingResult | 选定/候选映射、索引约定、方法、歧义、守恒信息 | 映射检查与端点配对 |
| SpeciesRecord | 结构引用、键图/身份依据、电荷/态、构象/同位素信息 | 结构比较与网络 |
| StepRecord | 两侧物种计量、TS/路径证据引用、方向、映射、假设 | 路径审计 |
| ThermochemicalResult | 来源能量、修正、条件、模型化学和量的类型 | 势垒与报告 |
| KineticResult | 使用的模型、势垒、条件、单位、假设和输出 | 基础速率比较 |

新 schema 随首个消费能力引入，不提前冻结所有高级领域模型。schema 定义可执行
数据形状，Claim 类型和研究策略继续保持开放。

## 9. 证据、验证与报告

已有身份、连通性、热化学、方法稳健性、pathway audit 模板可以复用。增加新的
确定性检查时，应有实际实现、输入条件和反例测试；不能仅增加一个
`xxx.complete=true` 字段就声称完成该领域验证。

优先补充原子守恒、映射双射/覆盖、物种/端点一致性、单位/条件兼容性、势垒
来源及速率适用条件等可执行检查。模式赋值、机制解释等科学判断仍需要明确证据
与 Agent 解释，模板不自动选择方法或认可整条机制。

报告至少显示：研究范围、条件、候选机制、物种与步骤、TS 证据、能量参考、
正反向势垒、适用的速率比较、未决分支、方法限制与来源链接。

复用现有渲染器，将多步/竞争路径数据适配为可检验的绘图输入。每个能量点、
步骤和结论能回到相关 Observation、Node 与 artifact。缺少数据的路径不能画成
完整且已接受的曲线；若使用示意高度，必须明确为无数值示意。

方法差异或多次计算的结果区间不自动解释成“真实机制的概率”。后续统计报告
需说明误差模型、采样分布、相关性和条件；未建立模型时报告敏感性或方法间差异。

## 12. 验收与评测设计

### 12.1 科学正确性测试

固定输入、算法设置、参考值与容差；输出来源可复核。至少覆盖：

- 多组分 SN2 的元素/电荷守恒、映射和端点重排；
- 质子转移中显式供受体、隐式氢展开及原子缺失的反例；
- 对称映射、立体化学变化、相同元素顺序但错误映射；
- 结构相似但电荷/电子态不同，禁止仅以 RMSD 合并物种；
- NEB 最高点尚未成为驻点、两个虚频、模式不符和 IRC 到达非目标盆地；
- 电子能/ZPE/G 不混用，条件不同不能静默比较，高层单点与热修正有明确绑定；
- 1 atm/浓度标准态、一级/二级速率单位和正反向一致性；
- 不满足简单分支条件时不输出通用产物比例；
- A+B → C+D 的计量、可逆环和催化循环，不误用研究 DAG 规则；
- 不完整、错误和超出适用范围的数据能输出可诊断结果，而非伪造完成。

### 12.2 合同与恢复测试

覆盖无效输入角色、未知能力、版本不匹配、来源变化、跨 Node 错误归属、重复执行、
事务失败及中断恢复。候选事实被修改后不能提升；历史接受记录是否当前仍由
原有 digest 与引用规则判断。

节点管理覆盖：有在途计算时暂缓后续研究；仅取消指定 Attempt；取消结果未知；
恢复开放节点；从终态节点分支；两个分支间切换焦点；用户指定节点与当前 focus
不同。读取上下文不能触发额外计算，暂停/取消不能悄悄改变科学 Claim。

### 12.3 Agent 自主性评测

使用相同模型、配置、工具环境和预算，在以下起点重复任务：

1. 只有反应定义，需要构造和检查输入；
2. 已有可靠 TS 候选，可直接研究驻点/连通性；
3. 已有可靠 IRC 与相关结构，只研究端点或热化学；
4. 存在映射歧义，需要补充信息或比较候选；
5. 首次搜索失败，需要判断重试、更换候选或新建分支；
6. 已有两条候选路径，研究范围限于给定条件的比较；
7. 执行中插入用户定向 Node 指令，检查范围和恢复。

评测判定科学证据、记录完整性和用户意图是否满足，不要求精确的工具调用序列。
合理的不同研究顺序都应通过。录制式 provider 测试只验证工具/状态集成，不能替代
实际模型自主选择的评测；建议每类模型试验重复至少三次并报告离散性。

### 12.4 协议负担与人机管理指标

M0 先建立基线，再设定版本的验收阈值：

| 指标 | 计量方式 | 改进目标 |
| --- | --- | --- |
| 行政字段与记录 token | 单独统计对象维护、合同查询和引用搬运；与科学推理分开 | 在同等记录质量下减少，建议以降低 25% 为初始目标 |
| 合同错误 | 首次有效调用比例、无效字段/引用和修复次数 | 核心案例不出现系统性重复错误 |
| 操作往返 | 记录/轮询调用与真正计算/分析调用分别统计 | 减少重复搬运；不以省掉科学检查为优化 |
| 上下文成本 | 单节点恢复的必要上下文、整体索引大小 | 历史增长时默认上下文保持有界 |
| 科学完成率 | 在相同预算下达到声明交付物的比例 | 不因新协议下降；报告未完成原因 |
| 管理可用性 | 用户定位文件、指定 Node、暂缓/恢复/切换的任务表现 | 意图作用范围准确，来源与历史完整 |

模型 token 若不可直接获取，应明确使用字符等代理指标，不能混为精确计量。
Node 数量减少不是成功指标；不通过合并节点来制造 token 改善。记录完整性与
用户管理能力是减负验收的共同条件。

### 12.5 发布检查

每个变更运行相关 Python/TypeScript/合同测试；涉及公共入口时执行 typecheck、
public-surface 和 package checks。发布前再运行适用的整体测试和干净安装 smoke。
文档规划阶段不启动远端科学作业；实际部署验证在实施阶段按选定目标进行。

真实小体系 smoke 应至少证明新分析能力可在安装环境运行，已有 CREST/NEB/
Gaussian 计算接口的衔接未受影响，且资料可在报告/Web 中沿 Node 找到。
可用性以选定 profile 的 doctor 和实跑回执为准，不绑定写死的机器名。

## 13. 版本、迁移与发布策略

1. 以新增能力和 artifact schema 为主；首批避免修改 Node/Claim/Acceptance 核心合同。
2. 能力 ID/version、参数、输出和 parser 作为完整测试单元发布，不能只注册描述。
3. 候选事实 producer 泛化若需要新协议版本，应在 M0 确定明确的兼容/迁移边界；
   保留历史文件及引用，提供必要的离线迁移检查，不在运行时偷偷转换旧记录。
4. 历史结果不因升级自动重新接受。已接受记录的旧版本证据保持可查看；新验证必须
   产生明确的新结果，不能重写原始科学结论。
5. 可选化学依赖在调用/doctor 时报告 readiness，不让未安装高级能力拖垮核心研究。
6. 每个小版本记录新增能力、适用范围、合同变化和实测结果；在安装包中验证新模块
   与 schema，而不只验证开发 checkout。
7. 与当前 App Server 迁移按稳定接口协调，科学能力无需等待客户端 UI 全面重做。

## 14. 首版完成定义与后续能力

首版完成需要同时满足：

- Agent 能从不同起点选择需要的能力，不必走同一研究流程；
- 反应输入、映射和多组分结构准备可以独立完成并表达歧义；
- TS 候选、驻点/模式、端点研究有清晰的 Node 与引用关系；
- 多个 Node 可共同支持同一个 elementary-step Claim；
- 在明确适用条件下计算自由能势垒与基础 TST 速率；
- 两条以上候选路径可以显式记录和比较，网络范围与未决分支清晰；
- 用户可定位节点结果、调整后续研究范围并管理特定在途任务；
- 报告和 Web 能从结论追到 Node、Observation 和源 artifact；
- 协议负担评测表明没有以牺牲记录、证据标准或管理粒度换取简化；
- 版本、安装与既有能力回归测试通过。

后续能力独立立项，按真实研究需求选择：

| 扩展 | 前置基础 | 特别需要验证的事项 |
| --- | --- | --- |
| 多构象/多方法比较 | 物种身份、热化学和采样来源 | 去重、平衡假设、TS 路径简并、采样遗漏、相关误差 |
| 微观动力学 | 有计量的网络、条件、速率 | 可逆性/详细平衡、守恒、非负浓度、刚性求解、时间依赖与灵敏度 |
| 实验约束对照 | 条件明确的 Observation 与动力学模型 | 反应级数、KIE、选择性等区分性预测及模型与实验条件差异 |
| 轨迹事件分析 | MD 轨迹、结构/映射合同 | 键事件阈值、产品归类、采样分布、分岔与统计不确定性 |
| MECP/自旋交叉 | 态身份、双面计算与专用 backend | 交叉条件、态跟踪、SOC 与速率模型的适用范围 |
| 激发态/非绝热 | 专用方法、轨迹和态证据 | 表面跳跃、态混合和统计收敛 |
| 显式溶剂/QM/MM/表面 | 环境与边界合同、专用执行能力 | 模型边界、采样、周期性、电化学储库和自由能定义 |

这些扩展各自增加输入、执行/分析、证据和测试能力，继续复用相同的 Node 记录与
人机管理方式。每项研究采用哪些能力，仍由 Agent 根据具体问题和证据决定。
