# CoRAgent 0.19 身份切换

这是不兼容版本，不是原地修改品牌文案。配套版本为 CoRAgent 0.19 与 CoRHub 0.20。
本文档存在不代表这两个版本已经发布。

| 范围 | 新标识 |
| --- | --- |
| 仓库 | `iawnix/coragent` |
| 主命令 / 可选 Web 命令 | `coragent` / `coragent-web` |
| npm / Python 发行包 | `@iawnix/coragent` / `coragent` |
| Python 内部导入 | `research_agent`，保持不变 |
| 环境变量 | `CORAGENT_*` |
| Host / Relay / Web 服务 | `coragent.service` / `coragent-relay.service` / `coragent-web.service` |
| Host / Link 协议 | `coragent-host/2` / `coragent-link.v1` |
| Host / 设备令牌 | `cah_` / `cad_` |

不提供旧命令别名、双协议、旧环境变量回退或旧安装格式读取。协议版本数字保留原有语义；
命名空间的变化本身就是不兼容的身份切换。

## 已有部署

1. 等待或明确停止正在执行的研究与科学任务。一起备份旧安装、外部工作区、Relay 数据库和配置，
   私密保存凭据，记录旧版本及实际服务名称。
2. 按实际安装的服务名称停止旧 Host、Web 和 Relay。用旧版本的卸载器移除旧服务和入口并保留数据；
   新卸载器只管理新安装，不负责清理旧部署。
3. 在新目录安装 CoRAgent，Relay 使用新状态目录。依据当前模板重建配置，改用 `CORAGENT_*`。
   不把旧安装标记、release 指针或环境收据复制到新根目录；绝对路径参与安装归属校验。
4. 向新 Relay 注册 Host，安装配套 CoRHub，在服务端执行 `coragent phone pair`，所有设备重新配对。
   令牌必须由新 Relay 签发，不能通过替换旧令牌前缀迁移认证。
5. 验证新建工作区、会话、消息、重连和 Monitor 操作，再恢复正式工作，并确认仅预期的新服务运行。

本次源码修改不会删除或重写已有研究文件。本版本不提供旧目录索引、会话或安装状态的自动导入。
不要直接重命名或搬动正在使用的工作区：其清单绑定绝对路径。保留备份不等于已经验证可导入；
如需转换历史状态，应对副本做单独的离线转换和验证，不在主程序加入旧格式回退读取。

## 回退

使用新版本工具停止并卸载新服务，单独保留切换后产生的研究。
将旧程序、旧配置和匹配的数据备份作为整套恢复，并使用对应旧客户端。
不要让旧程序读取新版本写入的状态，也不要用旧备份覆盖新增研究。

仓库网址与部署路径独立变更。本机源码路径及指定的私有测试根
`/home/iaw/project/TSPi/local_debug` 保持原位；测试数据不得上传或进入发行包。
