# 程序运行失败

在判断科学含义前，先把不同失败域分开。

## 排查顺序

1. 确认不可变 intent、Node、Backend、输入 Artifact 摘要和执行目标。
2. 任何重新提交或取消前，检查持久化控制保护与回执。
3. 区分 SSH/传输、调度器、远端启动、软件激活、scratch、程序、输出、解析和收集失败。
4. 收集所有实际存在的已声明输出，并在本地核验。
5. 只有主要 Artifact 支持时，才记录有科学意义的负面或异常 Finding。
6. 由 Root Agent 决定重试、重新计算、改变策略、新建 Node、向用户升级或停止。

## 常见类别

- **生效前失败**：调度器提交前的校验、本地准备或上传失败。只有类型化结果明确允许时，
  重试才可能安全。
- **外部效果不确定**：请求可能已到达调度器，但没有返回权威结果。必须协调确认，不能
  盲目重放。
- **远端启动失败**：科学程序生成主要输出前，激活、scratch 或 wrapper 失败。
- **输入失败**：程序报告 route、关键词、坐标、电荷、自旋或控制文件语法错误。
- **程序收敛/电子结构失败**：程序已经运行，但 SCF、优化、频率、IRC、电子态或数值
  计算失败。
- **解析失败**：存在有效或失败的主要输出，但本地解析器无法表达。保留 Artifact 和
  解析错误。

## 重试与新工作

只有 intent 未改变且已证明可以安全重试时才执行 retry。Recalculation 保留源 Node/intent，
并说明变化的参数与目的。当科学目标、假设、方法理由或分支发生变化时，新建 Node。

程序失败通常是运行数据。只有 Root 核验了科学后果，并记录支持该解释的 IssueFinding
或 FactFinding 时，它才可能反驳 Claim。

通过 calculation record 与 Node 保存持久摘要。只有运行错误具有已记录的科学后果时才
创建 IssueFinding；不要仅为了让运行错误可见而添加占位 Finding。
