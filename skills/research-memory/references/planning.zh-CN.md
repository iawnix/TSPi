# 规划与重访研究问题

复杂研究或新证据改变下一步选择时，使用本文。Node 关系组织问题，局部 plan 描述调查方法，用户任务控制仍由任务工具负责。

## 选择合适的问题粒度

一个问题能够独立解释结论、单独推进，或为多个其它问题提供证据时，适合单独建 Node。换命令、参数或初始构型本身不产生新问题。先建立已知且有用的问题，出现新的独立问题时再展开。

| 研究 | 合理组织 | 同一问题内的尝试 |
| --- | --- | --- |
| 分子性质 | 一个性质问题 | 准备输入、修复收敛、重复计算 |
| 竞争反应路径 | 分别调查的路径、共享方法检查、比较问题 | 初始构型、优化重试、路径验证 |
| 周期 DFT | 可独立解释的数值收敛与物理比较 | k 点/截断能样本；参数集合及结果表保留为材料 |
| MD/自由能 | 按需要分开平衡性、采样充分性或状态比较 | 重复轨迹、统计窗口 |
| 模型拟合 | 共享数据评估、分别比较的模型 | 参数搜索、重复拟合 |
| 理论推导 | 可独立使用的引理、近似适用性 | 代数、符号运算、局部修订；可以没有 Job |

根问题可选，多个任务入口可以表示互相独立的问题。子问题通过 `part_of` 指向总问题，共享问题可以有多个父节点。`requires` 表达真实研究依赖，不代表工具调用先后顺序；确实是替代思路时才用 `alternative_to`。比较结论引用精确的输入 Result。

创建或选取节点后，读取当前任务并关联入口与焦点：

```json
{
  "action": "set_research",
  "expected_revision": 3,
  "research": {
    "entry_node_ids": ["node_returned_for_the_study"],
    "focus_node_ids": ["node_returned_for_path_A", "node_returned_for_path_B"]
  }
}
```

替换为真实返回的 ID 和 revision。这次操作替换两份导航列表。焦点不是锁、排他所有权或资源授权。一个任务完成时，共享 Node 可以保持 open。只读浏览用 `research_read {ref}` 或 `{ref, field:"relations"}` 及返回的分页，不必更新焦点。

## 根据证据调整计划

恢复时将当前发现、待处理 Job 与用户目标和交付条件对照。下一次尝试有理由提供新信息时才继续该方法。某种方法达到尝试上限后，评估剩余已获授权的路线。Job 运行期间还有独立工作就继续；必须等这些 Job 的结果才能做其它有用工作时，才设置整个任务的等待。

执行错误需要诊断，本身不否定科学想法。检查失败后在原问题上调整方法。排除某个候选是有用的负面证据，不必因此结束整个问题或委托。

重访已关闭的问题时，读取当前字段，用 `research_update` 重开，并在 note 中说明原因和相关证据。只有独立问题或需要分别推进的分支才新建 Node。保留旧 Job、文件和 Result；适用时复用精确的旧证据，重复外部操作前先核对原回执。

修订已发布结论时，新建 Result 并设置 `supersedes`，适用时选择为当前综合判断。根据复核提醒检查受影响的比较和报告。提醒要求科学复核，不自动否定全部下游结论，也不自动重算。

## 留存进展并完成委托

计划和 note 解释决策，新 Result、固定材料和实际 Job 里程碑提供可恢复的进展。改写计划、增加节点、换组合引用相同证据都不补充推进额度。纯推导或规划任务可以把有用推导、完整方案本身保存为 Result/材料。

按用户交付条件给出相关不可变证据和局限。负面或不确定结论可以满足实际委托，但不能擅自降低用户要求的声明强度。Node closed、进程成功都不能单独证明完成。按限制停止无信息增益的重复尝试，分别判断局部方法失败与整个任务阻塞。
